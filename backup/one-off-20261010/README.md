## 为什么不是删掉

两者都**没进过 git**（`git ls-files` 为空），删掉就再也找不回来；而它们的**结论**已经在文档里，
脚本本身只是"怎么量的"那半份证据。所以挪到这里存档而不是删除：

* `scripts/` 下不再有"没有任何入口能跑到"的文件（`test:scripts` 的第 ③ 层）；
* `scripts/` 下也不再有**头部许了"跑完/量完即删"却不删**的文件（第 ④ 层）——这类脚本最坏的地方是
  **它会在几个月后被谁误跑一次**，而它做的事情是改文件；
* 结论要是想复核，文件还在，按原样 `node backup/one-off-20261010/_probe-whole-vs-sliced.js` 就能跑。

> 通用判据：**"量完即删"这句承诺，要靠一条常驻判据兜住，不能靠记性**（坑 40：纪律会被忘掉）。
> 现在它由 `test:scripts` 的第 ④ 层守着——往 `scripts/` 里放一个头部写着"跑完即删/量完即删"的文件，当场红。
> （判据认的是**那句删掉的承诺**，不是"一次性"这三个字：仓库里有三句正常描述带着这三个字，第一版把它们全判红了。）
