## ★ 最有价值的一条：Service Worker 缓存旧代码（真产品 bug）

- **现象**：改了 `client.js`/`style.css` 刷新不生效；服务器明明发了 `no-store`，DevTools 也是 200。
- **根因**：`sfu/public/sw.js` 把业务文件预热后 **cache-first**，而 **SW 完全不看 HTTP 缓存头**；
  且 SW 只在 sw.js 自身字节变化时重装，业务代码天天改、sw.js 不动 → 旧缓存永久生效。
- **修法**：按资源性质分两路——vendor 类库 cache-first；`client.js`/`style.css`/页面
  **network-first**（缓存只作断网兜底）。版本语义：改业务代码不必 bump，换 vendor 才 bump。
  另加逃生舱 `?nosw=1`（注销 SW + 清 Cache Storage + 自动重载）。
- **测试侧**：CDP 的 `Network.setCacheDisabled` **管不到 SW 的 Cache Storage** →
  E2E 每次必须清空浏览器 profile。
- 这段已写进 `LEARN.md` 5.31（教学价值最高的一节）。

## 1. 门禁边界修正（本轮最重要的判断）

subagent 第一版把 `/api/captions`、`/api/minutes`、`/minutes/*`、`/recordings/*` **也**上了
`requireAdmin` —— 这是个**会静默弄坏功能**的错。复核依据（都在代码里）：

- 登录卡有「游客进入」（`client.js` 的 `authGuestBtn`）→ **游客没有 token**；
- `/api/captions` 由 `client.js` **自动**调用（`capSentryFlush` POST 归档 / 导出与日报 GET）
  → 加 admin 门禁 = 游客字幕归档静默失效，只在控制台留一行日志。

**最终边界（已写进 `sfu/server.js` 的 `requireAdmin` 注释块，答辩可讲）**：
- 甲类·观测 = `requireAdmin`：`/api/rooms`、`/metrics`、`/api/recordings`
- 乙类·内容 = 刻意开放（能力=房间号/文件名）：`/api/captions`、`/api/minutes`、
  `/minutes/<房>/<文件>`、`/recordings/<文件>`
- `/dashboard` 页面本身不设门禁（否则打不开、没法提示去登录）
- 残余风险如实写：房号 10^6 可枚举、录像文件名是弱能力 → 生产该用房间内令牌 + 签名 URL

`test-sfu-signaling.js` 的 `httpReq` 默认带 admin token，会**掩盖游客视角的回归**
→ 加了 `noAuth` 开关，并用它跑了一条"游客无 token 也能归档+回读字幕"的端到端断言。

## 4. 优雅退出（新增"第 Z 部分"，原来**一个信号处理器都没有**）

Ctrl+C 原来是**直接暴毙**，三个后果：mediasoup Worker 变**孤儿进程**占着 40000-49999 RTC 端口、
`meeting.db-wal` 不做 checkpoint、ffmpeg 产物可能损坏。
现在 `SIGINT`/`SIGTERM`/`uncaughtException` → 关 Worker → 停监听 → `store.closeDb()`（WAL checkpoint）
→ 退出；幂等 + **5 秒保险丝**。并用 `shuttingDown` 标志修掉一个日志噪声：
正常退出时原来会打 `❌ mediasoup Worker 挂了，5 秒后自动补位`（演示时会以为崩了）。

⚠️ **Windows 投递不了外部 SIGTERM**（无 POSIX 信号，`process.kill` 走 TerminateProcess，
`timeout` 同理）→ 加了自测钩子 `TEST_SHUTDOWN_AFTER_MS`（沿用既有 `TEST_RECORD` 约定），
新增 `npm run test:shutdown`。
