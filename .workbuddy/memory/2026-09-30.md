### ① 白板延迟：测量推翻了直觉
新建 `scripts/bench-whiteboard.js`（真浏览器 + CDP：在真实页面派发拖拽事件，
用 `JSON.stringify` 探针数"发出多少条白板消息"，**纯外部观测不改业务代码**）。

| 指标（300 点拖拽） | 前 | 后 |
|---|---|---|
| board 网络消息 | **302** | **3**（-99%） |
| 事件处理耗时 | 9.2ms | 3.6ms |
| 一笔重绘 | 1.5ms | 0.3ms |
| 累积 1500 点重绘 | 1.5/1.7/**4.3** | 0.6/0.4/**0.6**（不再随点数增长） |

**CPU 只花 9ms —— 瓶颈不是计算，是消息洪水。** 每次 move 一条 SCTP 消息，
真机 1000Hz 鼠标=每秒上千条 → 排队 → 延迟累积。**本地回环测不出**（几乎不排队），
所以"本地很快"推不出"跨网没问题"。
修法：本地点立即画 + **网络按帧打包**（`pts` 批量协议，向后兼容单点）、
坐标 `toFixed(3)`、笔画期缓存 rect、接收端一批点一次描边、`redrawBoard` 一笔一条路径。

### ② AI 助理"卡"：不是模型慢，是渲染拖慢
流式每个 token 都 `textContent += delta` **然后** `scrollTop = scrollHeight`
——读 `scrollHeight` **强制同步布局** → 200 字答案 = **200 次强制 reflow**。
修法：增量攒批、**按 rAF 一次刷**（写入与 scrollTop 同帧）。
另外：查询改写让等待凭空多 1~3 秒而全程只有一句静止的"思考中…" →
由 brain 上报**真实阶段**（翻记录 → 换说法再找 → 组织回答），**零延迟成本的体感优化**。

### ③ 远程控制：固定帧率 → 闭环自适应
帧率开机写死 12fps：网好浪费带宽、网差帧堆积。**固定参数在变化的链路上必然一半时间是错的。**
控制端实测帧到达间隔（中位数）+ RTT → 回传 → 被控端只调本地限流间隔（下一帧生效）。
防震荡三件套：滞回死区 + 最小间隔 4s + 样本门槛（静止画面不出帧，不能当链路差）。
**两层范围分开**：策略 6~24 / 硬安全 2~24。控制律抽成纯函数 `rdDecideFps` 以穷举断言。

### ★ 修掉一个**假绿事故**（本轮最严重）
`test-agent.js` 原先**复用端口上已有的服务器**（"⚠️ 3001 已有服务器，复用它"）
→ **测试验的不是本次代码**。本轮我新加的断言全红、排查半天怀疑门禁/接线，
**真实原因是端口上那台是「上次被中断的测试」的孤儿进程（旧代码）**。
反面更危险：它也可能**全绿** = 验了个不存在的东西。
`test-sfu-signaling.js` 早就修过同一反模式，这次补齐到 `test-agent` / `test-e2e`
（后者没写"复用"分支，但端口被占时 ping 仍会 ping 到别人的服务器 → 同样假绿）。
三个脚本现在都是：专用端口（3011/3012/3013）+ 被占则明确拒绝 + 支持环境变量换端口。
> **假绿比假红危险得多：假红有人查，假绿没人发现。**
> **同项目同一个坑只修一半 = 半迁移 = 等于没修。改完一处要 grep 全仓找同类写法。**

另新增 `SFU_NO_HTTPS=1`（不去改用户的 config.json）——HTTPS(3443) 被占会让服务器
`process.exit(1)`，测试 spawn 时表现为"服务器未就绪"，看着像测试坏了、实则环境冲突。
